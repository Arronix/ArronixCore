# G07.2 — reading one serialized entity through the contract a browser admitted

**Status:** implemented; **not claimed as a closed gate.** Independent review is running, and G07.2's status
in the roadmap stays open until it reports. What is recorded here is what was built and what was observed,
including the real browser run and the two defects that run found.

Every claim below is a named fixture, a quoted command output, or an observation from a browser this work
actually drove. Where something was not proved, it says so.

## 1. What was built

G07.1 left a page holding contract assemblies whose bytes, CLR identity, build and universal-contract
reference had all been proved before the runtime saw them — and no way to read anything through them. G07.2
is that read.

Five parts, none of which names a media kind:

1. **A payload path.** `ContractPayloadLoader` takes one offer — an admitted contract, named by its
   declaring assembly and its entry point together — plus a path on the host that served the client. It
   fetches, deserializes through that contract and only that contract, proves the value and the projection,
   and returns what it proved.
2. **A projection proof.** `ProjectionAudit` walks the projection iteratively, bounded in every direction a
   contract-produced graph can be unbounded, and **captures what it proves as it proves it**.
3. **Address rules.** `BrowserAddress` decides what may become an `href` or a `src`.
4. **A panel.** `ContractPayloadPanel` renders the outcome and the projected fields, with stable identifiers
   for a driver, and owns its own state.
5. **A fixture and a driver.** `eng/proofs/fixtures/g07/movie.json` is generated by the movies contract's own
   writer; `eng/proofs/g07-browser-proof.mjs` drives the browser half.

## 2. Decisions worth stating

**Reading a contract's list once is not enough.** The obvious rule — read each list once, charge it, walk
it — is necessary and insufficient, because the report, the renderer and the proof all read the same objects
again afterwards. A list that answers safely while it is checked and returns a `javascript:` URL afterwards
would reach the document. So the audit returns a **trusted projection captured during the validating walk**:
every collection in it is this client's own array, and nothing downstream ever touches the contract's
objects. `AListThatChangesAfterItIsCheckedCannotChangeWhatIsRendered` and
`ADescriptorListThatChangesAfterItIsCheckedCannotChangeWhatIsRendered` are the witnesses; each uses a list
that answers differently on its second read, and asserts the entry was read exactly once.

**A descriptor's identity is proved on the input; a descriptor's content is copied.** Every projected field
must carry the schema's own descriptor object, at its own position — a dropped, reordered, duplicated or
merely equal-cloned descriptor is refused. That check is made against what the contract returned. What is
handed back is the copy, because a descriptor's `Components` and `Choices` are lists the contract owns.

**One budget, three dimensions.** Depth and a path-scoped open set close nesting and cycles. One node budget
covers every descriptor, value, item and choice across the whole walk, charged before any list is iterated,
so a list claiming `int.MaxValue` entries costs a refusal rather than an allocation. And one **character**
budget covers the whole rendering: each string is bounded on its own and the node budget bounds how many
there are, but 4,096 values × 65,536 characters is hundreds of megabytes out of a payload capped at four,
so the total is charged too — including addresses, in both shapes artwork takes.

**Failures are distinct problems.** Unsafe address, unavailable, deserialization, wrong deserialized runtime
type, projection threw, projected type mismatch, schema disagreement, value invariant, no admitted contract.
Each is a different place to look. None of them rewrites the installation report: the installation was
admitted correctly whatever a document turned out to be, and downgrading it would lose the one fact still
true.

**An offer is a capability, and it is re-proved.** The contract is checked by object identity against the
current installation before the fetch, after it, and again before any value is handed back, because a
withdrawal can land at any of those points. `Revalidate` is the same rule for values already on screen. Name
equality is not equivalent: a contract with the same name from another installation is another contract.

**Cancellation belongs to the caller.** A signaled token propagates. A cancellation nobody asked for — a
transport's own, a contract's own — is an ordinary contained failure, because reporting it as "the caller
abandoned this" loses the difference.

**A label is not a format.** Artwork may be inline, and the four raster media types are an allowlist; but a
payload labelled `image/png` that decodes to `<svg …>` is a document the browser parses. The decoded bytes
must carry the container signature the address claims. The base64 shape is checked before the decode, and
both padded forms are accepted — an earlier reading of "padding is at the end" refused every
two-character-padded payload, which is most of them.

**Artwork is a whole image.** Role, address, width and height survive projection, the captured graph, the
serialized proof and the rendered `<img>`. Reducing it to a URL loses the two facts that let a consumer pick
one of several images without fetching them.

**Absent is not empty, in the document as well as in the model.** A field the item has no value for reads as
a dash; a field holding an empty list says so. The tagged value keeps that distinction and the renderer was
throwing it away.

**A composite's parts are described by its components.** Both a list and a composite arrive as `Items`. The
renderer treated them alike, so every part of a composite was described by the field containing it: an
enumerated part showed its stored value rather than its declared choice, a counted part lost its unit, and a
nested composite rendered as nothing. The mutation is decisive precisely because the wrong answer still
looks like a rendering.

**The client carries no payload address of its own.** A default would be one installation's fixture path
compiled into every deployment — the same mistake as naming a media kind. The box starts blank and an
architecture rule holds the client's source to spelling no media assembly and no installation's own path.

## 3. The fixture

`eng/proofs/fixtures/g07/movie.json`, 1,976 bytes, written by the movies contract's own `Serialize` and
compared to it byte for byte by `MovieFixtureTests`. Regenerate with `ARRONIX_REGENERATE_G07_FIXTURE=1`; a
change to the movie graph, the wire form or the serialization options fails there rather than surfacing
later as a browser rendering less than it used to.

The graph is complete: artwork with roles and measurements, two ratings with their scales, voices and sample
sizes, the lifecycle its status is computed from, a collection with its own artwork and identifiers, external
identifiers, certification, translations, genres, keywords, runtime, popularity. Both images are inline
rasters — an 8×12 PNG and a 1×1 GIF — so the browser half fetches nothing and reaches nowhere, and the
declared measurements are the images' own.

**Two defects this run found**, both fixed and both re-proved:

1. A Blazor component with no parameters is never handed them again, so the panel read what could be
   projected once — before the installation had loaded — and kept that answer. In the real browser it said
   the page held no admitted contract while the page beside it said `Compatible`. Neither the desktop tests
   nor a reading of the code caught it; only the browser did. The page now passes the loader's report as a
   render trigger, and the panel states its offer count so a driver can see which answer it holds.
2. The panel shipped a default payload address. Removed, and held out by an architecture rule.

## 5. What this does not claim

1. **G07.2 is not declared closed here.** Independent review is running. The roadmap status stays open until
   it reports.
2. **The browser half is still not on the hermetic rail.** `eng/ci/run-tests.sh` carries no browser
   toolchain, and adding one would put a browser download in the clean-repository proof.
   `g07-browser-proof.mjs` makes the run repeatable rather than a one-off reading, but it runs beside the
   rail and needs Playwright's Chromium installed.
3. **G07A is open.** The path is generic and takes a verified contract plus a payload address, which is what
   an external consumer's contract will plug into. Nothing from the G07A branch was merged or copied here,
   and no part of G07A is claimed.
4. **G07.3 is open.** Update, removal, stale cache and stale tab are not exercised. The withdrawal rules this
   gate needed — an offer re-proved at each step, and a projection invalidated once its contract is gone —
   are in place and tested, but they are not a cache lifecycle.
5. **No provider result reaches this path.** The payload is a fixture served as a static file. Ingestion is
   G19/G28 work, and the deliberate absence of a test endpoint is why.
6. **Nothing is claimed about trimming.** The client still publishes untrimmed for the framework defect
   recorded in `client-contract-loading.md` §3.
